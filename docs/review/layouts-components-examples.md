# Mero layouts, components and examples

A developer can now open Mail, reply to a thread, inspect the returned HTML and read the server handler from the same page. All six layouts offer that path from a working screen to its implementation. [Try Mail](http://127.0.0.1:4173/layouts/mail)

## Changes from this review

- Each layout exposes its initial HTML, the actual HTTP exchange, the files to load and the relevant server source. The standalone view follows the selected record and appearance. CRM and Finance return only the workspace fragment when a filter changes. [Finance](http://127.0.0.1:4173/layouts/finance) · [Workbench checks](../../test/layout-workbench.test.mjs)
- The gallery serves a real phone capture to a phone visitor and a desktop capture on a wide screen. Each matches the active theme. Returning from an example lands on its gallery card. [Layout gallery](http://127.0.0.1:4173/layouts)
- Mail and Chat keep a separate draft per conversation in the current tab. A failed send keeps the message. If the user types while a send is pending, the new text survives the response. [Communication checks](../../test/communication-layouts.test.mjs)
- The component template stays visible when changing variants in source view. A failed script still leaves the template readable. Autocomplete lists the assets its selected variant needs. Charts and Markdown link their optional server renderers. Button demonstrates a pending request and retry. Switch explains a locked preference. [Local shortlist](http://127.0.0.1:4173/components/autocomplete?variant=Local%20shortlist) · [Button](http://127.0.0.1:4173/components/button?variant=Pending%20request) · [Switch](http://127.0.0.1:4173/components/switch?variant=Managed%20preference)

The catalog audit covered 738 route and theme combinations with zero reported failures. It now measures the rendered workspace width. A zero-width Mail workspace had passed the original overflow check. The local review produced 348 component captures and 48 layout captures of default and exercised states. [Audit](../../scripts/audit-catalog.mjs) · [How to run it](../../README.md#verify)

## What to take from the comparison

| Reference | What the public example shows | Decision for Mero |
| --- | --- | --- |
| HeroUI | Button gives loading, disabled and icon-only states their own examples. RangeCalendar shows how start and end dates share a month grid. [Button](https://heroui.com/en/docs/react/components/button) · [RangeCalendar](https://heroui.com/en/docs/react/components/range-calendar) | Give variants their own usage notes when behavior changes. Keep Mero’s two native date fields accurately described. A shared calendar grid is a separate scheduling decision. [Mero controls](../../site/components.mjs) |
| HeroUI Pro | Its public template index covers Dashboard, Mail, Chat, CRM and Finances. Mail opens with a thread list and tells the reader what to do in the empty detail pane. Finance connects a balance overview to transaction activity. [Templates](https://heroui.pro/docs/react/templates) · [Mail preview](https://template-email.heroui.pro/inbox) · [Finance preview](https://template-4.heroui.pro/) | Keep one identifiable task per layout. Mero Mail can reply and archive. Mero Finance can trace a balance to dated ledger entries. Use those tasks to introduce each screen. The comparison covers public pages and previews. [Mail implementation](../../site/communication-layouts.mjs) · [Finance implementation](../../site/business-layouts.mjs) |
| shadcn/ui blocks | The dashboard puts Preview, Code and a full-page view together. Its file tree separates the page, data, chart and table. [Dashboard block](https://ui.shadcn.com/blocks#dashboard-01) | Put the working app, its actual template and the relevant server file within reach on the same page. Keep a direct link to the standalone app for checking it at full width. |
| Radix Primitives | Dialog documents where focus goes on Escape. Tabs documents how horizontal and vertical arrow keys move between triggers. [Dialog keyboard behavior](https://www.radix-ui.com/primitives/docs/components/dialog#keyboard-interactions) · [Tabs keyboard behavior](https://www.radix-ui.com/primitives/docs/components/tabs#keyboard-interactions) | Check the next keystroke after a swap. Closing the inventory editor should return focus to the edited row. Switching documentation tabs should leave focus on the selected tab. [Inventory regression](../../test/core-browser.test.mjs) |
| daisyUI | Its HTMX guide uses ordinary HTML and server fragments. Its drawer example keeps navigation visible on a wide screen and exposes a toggle on a small screen. [HTMX guide](https://daisyui.com/htmx-component-library/) · [Responsive drawer](https://daisyui.com/components/drawer/#responsive-sidebar-is-always-visible-on-large-screen-can-be-toggled-on-small-screen) | Show exactly which files the copied example needs. Check navigation at phone width with a real task, such as opening a thread, replying and returning to the list. [Mail and Chat checks](../../test/communication-layouts.test.mjs) |
| Blossom Carousel | The basic examples isolate snapping, thumbnails and right-to-left navigation. Its accessibility guide describes labelled controls, current-slide state and focus after navigation. [Examples](https://blossom-carousel.com/docs/examples) · [Accessibility guide](https://blossom-carousel.com/docs/a11y/accessibility-guide) | On Mero’s lamp, the selected thumbnail, caption and displayed finish must agree after a drag or a keypress. Keep the existing keyboard regression and the physical touch-device check. [Gallery behavior](../../public/mero-gallery.js) · [Open device checks](../quality-review.md) |
| HTMX | Click to Edit puts the read view, edit form and replacement response together. Inline Validation shows the returned field markup with the submitted value and correction. [Click to Edit](https://htmx.org/examples/click-to-edit/) · [Inline Validation](https://htmx.org/examples/inline-validation/) | Show the response generated by the action a visitor actually took. For a failed settings save, the visitor should see the HTTP 422, their submitted name and the field error, then be able to inspect the successful retry. [Playground regression](../../test/playground-journey.test.mjs) |
