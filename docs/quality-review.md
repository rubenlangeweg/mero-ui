# Mero UI quality review

**The biggest defects showed up when a second request, a second component or a second browser tab entered the picture.** They could make a successful save look invalid, apply an old response to a new selection, or overwrite another person’s edit. The fixes below have repeatable checks. [Browser tests](../test/) · [Full component coverage](component-coverage.md)

## What changed

| Surface | What we reproduced | What to try now |
| --- | --- | --- |

## Visual decisions

The homepage keeps its graphite palette and lamp photography. The featured card reads the actual SKU, category, status and saved finish. The edit action sits beside the swatches and carries the chosen finish into the inventory editor. Editing or deleting the featured record updates the card.

The two large frames below the hero now contain a filterable report and a working conversation about the same shipment data. Their headings align on desktop. On mobile the examples stack, and opening the chart table expands the frame to fit. [Desktop capture](review/home-desktop.png) · [Mobile capture](review/home-mobile.png)

## Browser coverage

Every pull request and release runs the full test suite in Chromium, Firefox and WebKit. Set `MERO_BROWSER` to select an engine locally. The catalog audit runs in Chromium. Drawers dim the page behind them. Full-screen backdrop blur stalled the inventory drawer in Linux WebKit and left Save outside the viewport during the slide. [Local verification](../README.md#verify)

Then give a developer new to Mero the published quick start and a backend fixture. Time their first successful edit and handled validation error against the proposed 15-minute target.

## Screen-reader review for admin workflows

**Manual runs pending on both platforms.** Run each script once with VoiceOver and Safari on macOS and once with NVDA and Firefox on Windows. For each step, record the browser and reader versions, keys used, focused item and words spoken. Mark missing speech, duplicates and unexpected focus moves.

Start the catalog with `npm start`. Open the standalone previews linked below. In Safari, enable “Press Tab to highlight each item on a webpage”, start VoiceOver with Command F5 and turn Quick Nav off for the widget keys. In Firefox, start NVDA and use NVDA Space to switch to focus mode when arrow keys move the reading cursor. Use the reader’s browse commands to inspect headings, table headers and group names.

1. **Menu button.** Open the [Menu Button preview](http://127.0.0.1:4173/preview/menu-button). Tab to “Actions for Arc Task Lamp”. Record its name and collapsed menu-button state. Press Down. Focus should move to “Open details” in “Arc Task Lamp actions”. Press End to hear “Delete” and its unavailable state. Press Enter, then Escape. The menu should stay open through Enter and close on Escape, with focus back on the same button. Repeat with “Actions for Halo Pendant” and listen for the new record name.
2. **Combobox.** Open [Autocomplete](http://127.0.0.1:4173/preview/autocomplete). Tab to “Workspace”, type `cob` and pause. Listen for one suggestion. Press Down and listen for “Cobalt”, selected. Press Enter and check the collapsed input contains “Cobalt”. Replace the text with `not-a-workspace`, immediately press Escape, then Down and wait. Check that the empty result is announced and that Down never reads a previous option.
3. **Grouped commands.** Open [Command Menu](http://127.0.0.1:4173/preview/command-menu). Tab to “Search commands”, then press Command K on macOS or Control K on Windows. Listen for the Commands dialog and five results. Move Down through Pages into Actions. Record when each group name is spoken. Home should take you to Button and End to Export catalog. Press Enter. Listen for “Export requested” once and verify focus returns to Search commands. Reopen and press Escape twice. After the first press the collapsed input keeps focus. After the second, focus returns to the opener.
4. **Action outcomes.** Open [Action Button](http://127.0.0.1:4173/preview/action-button). Tab to “Retry export” and press Enter. Listen for “Export restarted.” once and verify focus stays on Retry export. Repeat with “Revoke key” and “Halt run”. Record the refusal and the unknown-outcome warning separately. To inspect the transient busy state, repeat Retry export with a slow network profile and query the focused button while waiting. It should keep its name and expose its unavailable state.
5. **Back to a filtered row.** Open [Filter Chips with Draft applied](http://127.0.0.1:4173/preview/filter-chips?status=Draft). Read the Product column header and its ascending sort direction. Activate the Product sort link and check that the direction changes to descending. Tab to the Halo Pendant link, press Enter and check the detail heading. Use Command Left Bracket in Safari or Alt Left in Firefox for browser Back. Check that focus returns to “Halo Pendant, link” and that the Draft filter and descending sort remain. Repeat at a 390 px viewport with the card layout.
6. **Typed confirmation.** Open [Typed Confirmation](http://127.0.0.1:4173/preview/typed-confirmation) and activate “Delete environment”. Record the alert dialog name, the Confirmation phrase label and its description. Enter `acme/production/delete` and check the hint asks for a reason. Enter `test`, then submit. Focus should land on the invalid Reason field and its description should explain the eight-character minimum. Replace the reason with `Retire unused environment` and submit again. Listen for “Demo deletion confirmed.” once and check that focus returns to Delete environment. Repeat with the [Unknown outcome variant](http://127.0.0.1:4173/preview/typed-confirmation?variant=Unknown%20outcome). Submit the valid phrase and reason. The dialog should stay open and announce the unknown outcome.
7. **Live progress.** Open [Live Progress](http://127.0.0.1:4173/preview/live-progress). Find the “Production deployment” region. Read the initial Queued status and wait for Running, then Succeeded. Count one live update for each change. Wait another six seconds and check for silence. Reload, switch to another tab while queued, wait six seconds, then return and listen for the current status. To check recovery on localhost, reload, then stop the catalog server with Control C in its terminal. Return to the preview for two polls. Verify the last good status stays readable and the retry message is spoken once. Tab to “Retry now” and press Enter while the server is still down. Keep focus there, restart the server with `npm start` and return to the preview. Record the recovered status and the focus destination.

The [browser regression](../test/admin-accessibility-browser.test.mjs) checks the ARIA tree, focus, state attributes and live-region text writes. Chromium also checks the native accessibility tree for all seven interactions, including busy, disabled, focused, selected, modal and live properties. The v0.6.0 release check also queried Firefox’s native accessibility roles and names with WebDriver BiDi and checked state and focus on the matched elements. Across seven workflows it recorded 39 observations. The manual runs establish what people hear.

**Issues found and fixed**

- A copied form dialog could return focus to the first instance after a save. Scoped snippets now rewrite ID selectors for both the return control and its fallback.
- The Menu Button example now connects each named Actions button to its own menu with `aria-controls`. The relation follows the renamed IDs when the example is copied.
